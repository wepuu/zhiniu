# Authentication and registration access

Zhaoniu uses opaque, server-side sessions. The browser receives an HttpOnly session cookie and a
separate readable CSRF cookie. Every cookie-authenticated write must present the CSRF value in
`X-CSRF-Token` and pass the allowed-Origin check.

## Invitation-only registration

Public self-registration is disabled. `POST /api/v1/auth/register` requires an invitation code in
addition to email and password. Invitation codes are generated by an operator:

```text
uv run python -m zhaoniu_api.cli generate-registration-invites --count 10 --expires-in-days 7 --name internal-beta
```

Only the generated plaintext values may be handed to intended recipients. The database retains an
HMAC digest, code prefix, batch, expiry, revocation state and atomic consumption metadata; it never
retains the complete code. A code is single-use and registration consumes it in the same database
transaction that creates the user.

New invitation registrations receive the versioned `basic` access baseline. Accounts created
before the Phase 11 migration retain the versioned `legacy_beta` baseline so deployment does not
silently remove existing capabilities.

## Operator safety

Invitation and activation secrets must be different, non-default values in production. They are
configuration secrets and must not enter logs, database rows or version control. Rate limiting is
fail-closed in production when Redis is unavailable. Email verification, password recovery and
account deletion remain outside Phase 11.
